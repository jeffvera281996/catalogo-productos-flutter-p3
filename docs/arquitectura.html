NexoShop — Arquitectura por capas

Flujo de dependencias de arriba hacia abajo: cada capa solo conoce a la inmediatamente inferior. Inyeccion de dependencias en main.dart con MultiProvider.
1. Presentacion (UI) lib/ui/
SplashScreenCarga inicial + permiso de notificaciones
HomeScreenCatalogo, pull-to-refresh, origen de datos
DetailScreenFormulario de pedido + FotoAdjuntaField
PedidosScreenHistorial y estado (pendiente / enviado)
OfflineBannerGlobal en MaterialApp.builder
↓context.watch / select (reconstruye)
↓context.read (acciones)
2. Gestion de estado — Provider / ChangeNotifier lib/providers/
ConnectivityProviderEstadoRed + WidgetsBindingObserver (ciclo de vida)
CatalogoProviderProductos, origen (remoto / cache / semilla), anti-recarga duplicada
PedidoProviderCrear pedido, cola offline, sincronizacion con Future unico
↓llamadas a metodos
↑Stream<bool> cambios de red
3a. Servicios nativos lib/services/
ConnectivityServiceStream, debounce 600 ms, verificacion DNS
PermissionServiceRuntime permissions → enum propio
ImageServiceCaptura → recorte → JPEG 70 %
NotificationServiceCanales Android, permiso, toques
3b. Datos lib/data/
ProductoRepositoryNetwork-first → cache → semilla
PedidoRepositoryPersistir primero, enviar despues
RemoteDataSourceApiClient http, timeout 8 s
LocalDataSourceshared_preferences (JSON)
↓plugins (MethodChannel / Pigeon)
↓HTTPS
4. Plataforma Android / iOS
connectivity_plusConnectivityManager / NWPathMonitor
permission_handlerDialogos de permiso del sistema
image_picker + image_cropperCamara, Photo Picker / PHPicker, uCrop
flutter_local_notificationsNotificationManager / UNUserNotificationCenter
API RESTdummyjson.com
Desacoplamiento: ninguna pantalla usa directamente red, permisos, camara ni notificaciones; lo hacen los servicios. Cambiar un plugin no toca la UI.
Transversal: lib/core/ (tema, colores, textos de marca y excepciones de dominio).
